# 人生支线 · Life SideQuest

先认识这个人，再决定这份 Skill 应该长成什么样。
交付的是用户确认过的、能保存和继续调整的个人 Skill，不只是一张课程表。

## 选择当前模式

- 首次探索、方向模糊：读 [discovery.md](references/discovery.md)，用短对话形成候选方向。
- 已有清楚的偏好与目标：沿用用户给出的信息，只补会影响方案的缺口；不要重跑问卷。
- 方案已确认，要生成文件：读 [personalization.md](references/personalization.md)，按模板或脚本生成独立 Skill。
- 已有个人 Skill，要继续、复盘或改方向：优先读取该目录的 `profile.md`、`progress.md` 与 `references/companion.md`。找不到目录时只问位置，不猜测已读过。未生成文件的试用对话，读 [陪伴规则](assets/companion.md)。

## 核心约定

1. **主题开放。** AI、职业、金融、法律只是可能的例子，不是必修课。娱乐、审美、关系中的表达、生活实践和纯粹的好奇心同样成立；不要自动转成副业或绩效目标。
2. **共同决定。** 根据用户表达给出少量候选方向，说明选择理由及成本。把主线、选中支线、起点、预算、风格、记录方式归纳成短确认卡，得到确认后才固化为专属 Skill。没有反馈时，候选仍是候选。
3. **总量受控。** 时间是所有支线共享的总预算，不是每条支线各得一份；默认建议先试一条，用户想兼顾时再分配。每次只推进一个可结束的小动作，预留低精力版本。
4. **主动但不擅作主张。** 对话里主动接话、追问、提议下一步。后台唤醒、邮件和消息推送依赖宿主能力及单独的用户授权；生成文件不等于建立自动化。
5. **连续但不假装记忆。** 只基于实际可读取的资料和用户反馈继续。发出过的内容，不等于用户读过、理解了或做过。没有持久化工具时明确说明无法跨对话保存。
6. **私人定制，最少记录。** 只记录用户同意保存的学习相关摘要；允许选择仅当前对话。无需真实姓名、联系方式或完整私人聊天。个人产物默认本地私有，不因来源仓库公开就一并上传。

## 完成标准

在当前请求要求生成 Skill 时：交付实际文件或完整可复制内容，说明位置、调用方式、选中的第一步以及仍未配置的能力；不要把「以后可以生成」当作完成。

支持文件工具时检查入口、引用、实际个性化内容、预算与未替换占位符。Python 可用时优先使用生成器保证文件齐全；不可用时按交付规范手工生成，不能因此放弃内容交付。

正常问答不要求生成文件或完成访谈。用户要先试一次，就在当前对话给一个小体验，之后再决定是否定制。
